# Feature Priorities 

These priorities describe the planned project. AI findings support a human reviewer; they do not make the final decision.

priority | Features | User stories

| Must | Secure sign-in and role-based access | US-01, US-09 |
| Must | Create applications and upload documents with file checks | US-02 |
| Must | Applicant status page and reviewer queue | US-03, US-04 |
| Must | View original documents and extracted fields; allow corrections | US-05 |
| Must | Verification report with findings, explanations, and sources | US-06 |
| Must | Human reviewer records the final decision and justification | US-07 |
| Should | Reviewer can request additional documents | US-08 |
| Should | Administrator can manage versioned verification rules | US-10 |
| Should | Audit history for important actions | US-11 |
| Could | Reviewer chat with answers grounded in application data and sources | US-12 |
| Won't | Automatically make the final decision without a human reviewer | US-07 |
| Won't | Claim the system can prove a document is authentic | US-06 |
| Won't | Use real personal documents for development or testing | US-02 |

## Priority meanings

- **Must:** needed for the first working version.
- **Should:** useful, but the first version can work without it.
- **Could:** optional if time allows.
- **Won't:** outside this project's planned scope.
